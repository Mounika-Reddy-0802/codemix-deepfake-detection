# HiACC child-quarantine check (W3-T2)

> ## ⚠️ Incident, 12 August 2026 — the automatic quarantine silently failed
>
> On the real HiACC download, `scripts/01_download_data.sh` reported
> *"moved 0 folder(s)"* and completed successfully. It had quarantined **nothing**.
> `Corpus/children/` — **1,858 child utterances** — was sitting in the live corpus.
>
> **Two independent bugs, both silent:**
>
> 1. `grep -P` fails on Git Bash with *"-P supports only unibyte and UTF-8
>    locales"*. It exited non-zero, `|| true` swallowed the error, and the loop
>    received an empty list.
> 2. The pattern was `(?i)child|kid|minor`. `(?i)` is a PCRE construct — under
>    POSIX `-E` it matches nothing, so even with grep working the sweep would
>    have found no folders.
>
> Either bug alone produces "0 folders moved" — **indistinguishable from a corpus
> that genuinely has no child data.**
>
> **Caught by:** `python -m src.data.quarantine`, which uses Python's own regex
> and reported *"1 child-looking item(s) outside quarantine"*.
>
> **Resolved:** `Corpus/children/` moved to `_EXCLUDED_children/children/`.
> Script now uses `grep -Ei` with a POSIX pattern, and — the actual lesson —
> **verifies the result afterwards and calls `die` if anything child-looking
> remains outside quarantine.** A sweep that reports success is not evidence;
> a post-condition check is.
>
> **No child audio was ever processed.** The failure was caught between
> extraction and the first preprocessing run.
